# Tier 2 Label Source Audit & Documentation

**Audit Date:** 2026-10-18  
**Scope:** Investigation of how Tier 2 pseudo-labels and ground-truth verdicts are produced during the unseen-attack adaptation loop.

---

## Executive Summary

A critical question in the evaluation of two-tier adaptive intrusion and malware detection systems is:
> **Are the labels fed back to Tier 1 generated by an autonomous verification model (pseudo-labels) or by an omniscient oracle using dataset ground truth?**

Our forensic audit of `src/evaluation/run_unseen_multi_attack_loop.py` revealed an important discrepancy between the stated design and the initial implementation:

1. **Dual Representation Artifact:** 
   In `src/evaluation/run_unseen_multi_attack_loop.py` lines 178–180, incoming network flows were paired with randomly sampled static PE feature vectors (`X_orig_t2`) from the EMBER 2018 corpus.
   
2. **Untethered Model Call:**
   In line 237, a trained `RandomForestClassifier` (`tier2_rf`) predicted verdicts on these random EMBER samples:
   ```python
   esc_t2_X = batch_X_t2[esc_mask]
   tier2_verdicts = tier2_rf.predict(esc_t2_X)
   ```

3. **Ground-Truth Bypass (Oracle Feedback):**
   In line 243, however, the retraining set was populated using the CIC-IDS dataset's ground-truth labels (`batch_y_t1[esc_mask]`), rather than `tier2_verdicts`:
   ```python
   X_train_t1.extend(batch_X_t1[esc_mask])
   y_train_t1.extend(batch_y_t1[esc_mask])  # <-- Dataset ground truth, bypassing tier2_verdicts!
   ```

---

## Implications & Risks

### 1. The "Oracle Tier 2" Assumption
By using `batch_y_t1[esc_mask]`, the original experiment evaluated an **Oracle Tier 2** baseline (where Tier 2 has 100% accuracy on escalated payloads). 
While evaluating an Oracle baseline is a standard upper-bound ablation in the literature, presenting it as an autonomous deep model obscures the real-world error propagation:
- Real deep models (e.g., full-text n-gram analyzers or static PE engines) have an imperfect False Discovery Rate.
- If Tier 2 emits a false negative or false positive, Tier 1 ingests a corrupted label.
- Over multiple feedback cycles, noisy pseudo-labels can poison the edge classifier boundary.

### 2. Modality Mismatch (Network Flows vs. EMBER PE Vectors)
Network traffic (CIC-IDS 2017) and Windows PE binaries (EMBER 2018) belong to fundamentally different protocol layers. Pairing a network flow's escalated state with a random PE vector is non-physical.

---

## Concrete Resolution Plan

To uphold **Project Rule 1** (No fabricated or hardcoded numbers) and **Task 4** (Make Tier 2 real and match data to the application layer):

1. **Explicit Baseline Labeling:**
   - Clearly label the oracle experiment as `baseline_oracle_tier2` where Tier 2 is assumed perfect.
   - Contrast this with `trained_tier2_model` where Tier 2 is a real model trained on held-out deep features.

2. **Application-Layer Alignment (Tracks A and B):**
   - **Track A (HTTP Payloads):** Use CSIC 2010 and CIC-IDS2017 Web Attacks (SQLi, XSS, Brute Force). Tier 1 extracts fast headers/lengths; Tier 2 runs a full-text TF-IDF / character n-gram deep verification model trained on a separate split. Both tiers inspect the **same HTTP request**.
   - **Track B (File Uploads):** Extract static PE features using EMBER/LIEF from genuine files (clean system binaries vs. MalwareBazaar malware). Tier 1 inspects lightweight PE headers (entropy, size, subsystem); Tier 2 evaluates the complete 2,381-dimensional EMBER static vector.

3. **Poisoning & Error Bounds:**
   - Implement Phase 5 bounds (Algorithm 2 safety): pseudo-label confidence gating, sample weighting, and influence caps so that Tier 2 misclassifications cannot corrupt Tier 1.
